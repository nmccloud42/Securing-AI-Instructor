
# Securing AI — Instructor Grading Guidelines

## Overview

Students complete personal copies of the seven student `.ipynb` notebooks on designated cyber range machines using VS Code. Instructors evaluate submissions using the corresponding **private instructor notebooks**.

## Before Grading

- Confirm the student's submitted `.ipynb` file is their completed working copy.
- Check the module requirements and reference solutions.
- Consider whether the student could execute required experiments in the provided cyber range environment.
- Do not expect identical numerical outputs where randomization or environment differences are reasonable.

## Suggested 100-Point Framework

| Category | Points |
|---|---:|
| Required activity completion | 20 |
| Technical implementation | 30 |
| Experimental analysis | 20 |
| Written explanations | 15 |
| Final practical assessment | 15 |
| **Total** | **100** |

This is a proposed shared framework. Module-specific requirements and the instructor's approved rubric take precedence.

## Evaluation Guidance

- **Activity completion:** Required cells, written answers, and lab steps are present.
- **Technical implementation:** The student used appropriate methods and correct code.
- **Experimental analysis:** Findings reflect actual outputs and relevant security implications.
- **Written explanations:** Reasoning is accurate, clear, and appropriately justified.
- **Final assessment:** The student applies module concepts to the assigned practical exercise.

## Operational Notes

The cyber range administrator/instructor should document how student work persists between sessions and how completed `.ipynb` files are transferred for submission. Do not assume all cyber range desktop or temporary directories are persistent. Keep grading records and student submissions in approved private systems.
